# 変動率モデルでB2の買付額を調整する試み

実施日：2026-09-26。別プロジェクト `../kabu` の変動率モデルが出す「翌営業日の予測変動率」で、
B2の1日の買付額を増減させた。結論から書くと、**リスクは下がったが、リスク調整後の成績は
改善したと言えない。** 本番の設定（`config.b3l_2026_*.json`）には入れていない。

## つなぎ方

あちらのモデルは日本時間16:00に、翌営業日の Parkinson分散（高安値から計算する日中変動、%²）を
予測する。B2は前営業日の引けまでで銘柄を決め、当日10:30〜14:00に注文して15:30の引けで買う。

したがって買付日 D に使えるのは「D-1 の16:00に作られた、D を対象とする予測」で、
これはB2の選定に使う情報と同じ締め切り（D-1の引け）に収まる。未来の情報は混ざらない。

```
D-1 15:30  引け  → B2が銘柄を決める / 変動率モデルが D の予測を出す(16:00)
D   10:30〜14:00 注文（このとき予測σで買付額を決める）
D   15:30  引けで買い
D+1 09:00  寄りで売り
```

倍率は `目安σ ÷ 予測σ`。目安σは直近250営業日の予測σの中央値（その日までに分かっている分だけ）。
σの分布は右に偏るため倍率をそのまま使うと平均が1を割るので、過去の倍率の平均で割って
平均1にそろえている。

## 使い方

```powershell
powershell -File ps\Import-VolatilityForecast.ps1                      # ../kabu から予測を取り込む
$env:KABU_CONFIG = "ps/config.b3l_vol_2024_top10.json"; powershell -File ps\Simulate-SKabu.ps1
```

取り込み先は `data/processed/vol/nikkei_vol_forecast.csv`（666件、対象 2024-01-04〜2026-09-28）。
元ファイルのSHA-256は `data/processed/vol/source_meta.json` に残す。
N225の営業日で予測が欠けている日は0件だった。

設定はシナリオごとに書く。

```json
"volSizing": {
  "csv": "data/processed/vol/nikkei_vol_forecast.csv",
  "minScale": 0.5, "maxScale": 1.5,
  "warmupDays": 60, "medianWindowDays": 250,
  "normalizeMean": true, "onMissing": "one"
}
```

`targetSigmaPct` を入れると中央値の代わりに固定のσを目安にする。
`onMissing` は予測が無い日の扱い（`one`=倍率1 / `skip`=買わない）。
`close_to_open_lag1` のみ対応し、他のモードでは例外を投げる。

## 結果（2024-01-05〜2026-09-25、663取引日、上位10銘柄、コスト3bp・税引後）

| シナリオ | 平均買付 | 年率 | 日次σ | Sharpe | 最大DD | 年率/DD |
|---|---:|---:|---:|---:|---:|---:|
| flat（資産の100%） | 507,750円 | 16.6% | 0.681% | 1.44 | −10.8% | 1.54 |
| flat_matched（85%固定） | 417,200円 | 13.8% | 0.578% | 1.43 | −9.2% | 1.50 |
| volsized（変動率で調整） | 430,432円 | 12.4% | 0.505% | 1.48 | −8.1% | 1.55 |

`flat` とそのまま比べると張りの量が違って比較にならないので、平均の買付額をそろえた
`flat_matched` を並べた。**なぜ揃わないかは下の「構造的な制約」のとおり。**

張りをほぼ揃えた `volsized` − `flat_matched`（volsizedの方が平均買付は3.2%多い）：

- 日次リターン差 **−0.500 bp/日、t値 −0.86**（有意でない）
- Sharpe **+0.051**、年率 **−1.39pt**、最大DD **−1.14pt**（DDは改善）

銘柄選定は壊していない。建玉あたりの日次成績は調整の有無で 8.86bp → 8.84bp、
Sharpe はどちらも1.70で一致した。つまり効いているのは買付額だけである。

## 構造的な制約

`budgetRatio: 1`（資産の100%）が上限だと、倍率が1を超えても `Min(買付上限, 買付余力)` で
現金不足に切られる。**減らす方向だけが効き、増やす方向が効かない。** このため
平均の張りは調整なしより必ず細くなる（今回は85%相当）。

倍率を両方向に効かせるには、基準の `budgetRatio` を1より下げて余裕を作る必要がある。
信用を使わない前提では、変動率調整は「危ない日に張りを抑える装置」であって、
「同じ張りで成績を上げる装置」にはならない。

## 判定と注意

**リスク調整後の改善は確認できない。** DDは1.14pt下がったが、年率は1.39pt下がり、
日次リターン差の t値は −0.86 で有意でない。Sharpeの+0.05は663日では区別できない。

- 評価期間 2024-01〜2026-08 は、**あちらのモデルが最終評価に使い切った期間**である。
  あちらの報告が「この期間を新しい未評価データとして扱ってはいけない」と明記しており、
  今回の組み合わせの検証も未評価データでの結果ではない。
- 予測対象は日経平均の日中変動、B2が負うのは個別株のオーバーナイトの窓。別物を代理に使っている。
- 予測が揃うのは2024年以降のみ。2022〜2023年は年次モデルが存在せず検証できない。
- あちらのモデルは2024年に平均分散を約26%過小評価している。危ない日に張りを抑えきれない年がある。

## 残っている手

1. 基準の `budgetRatio` を0.8程度に下げ、倍率を両方向に効かせて再評価する。
2. 日経平均の日中変動ではなく、B2が実際に負うオーバーナイトの窓の大きさを予測する。
   これはあちらのモデルの作り直しになる。
3. 個別銘柄の変動率で銘柄ごとの配分を変える（今回は日次の総額だけを動かした）。
4. 2026年9月以降の、どちらのモデルも見ていないデータで判定する。台帳は
   `reports/forward_test/` に積み上がっている。
